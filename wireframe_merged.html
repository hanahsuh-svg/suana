FAQ

기존 OpenAI 코드에서 바로 쓸 수 있나요?

네. base_url을 MoFAC 주소로, model을 motif-3으로 바꾸면 돼요.

캐시 입력 가격은 언제 적용되나요?

이전 요청과 앞부분이 같은 입력은 자동으로 캐시 가격으로 계산돼요. 따로 설정할 것은 없어요.

요청 한도(레이트리밋)는 얼마인가요?

분당 요청 x회 · 분당 토큰 x개 (확인 필요)

모델 버전이 바뀌면 어떻게 되나요?

교체 · 종료 최소 x일 전에 새 소식과 이메일로 알려드리고, 대체 모델을 안내해요.

Quickstart

Morph API는 OpenAI 표준 규격을 완벽하게 지원합니다. 기존 코드에서 Base URL과 API Key만 변경하여 즉시 사용할 수 있습니다.

1. API Key 발급

콘솔에 로그인하여 API Keys (C-02) 메뉴에서 Bearer 인증에 사용할 Secret Key를 발급받습니다.

2. cURL 예제 (Chat Completions)

curl -X POST https://api.morph.com/v1/chat/completions \
  -H "Authorization: Bearer $MORPH_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "motif-3", // glm-5.3 · kimi-k3 로 바꾸면 모델 전환
    "messages": [
      {"role": "system", "content": "You are a helpful assistant."},\br/>       {"role": "user", "content": "Hello!"}
    ],
    "stream": true
  }'

C-03 충전 영역의 카드 목록에서 바로 처리 — 카드 선택(✓, 이번 결제에 쓸 카드) · [＋ 다른 카드 추가](삭제 버튼 없음 — 10/14) → addPaymentMethod(). 그 밖의 설정은 “등록 카드로 결제” 오른쪽 [결제 관리] → openSettings() 토스 결제 관리 화면(결제수단 관리(카드 삭제 포함) · 결제 비밀번호 · 원터치결제 · 생체인증). 별도 MoFAC 관리 페이지 · 기본 카드 지정 UI는 만들지 않음.

                

              

      
📝 C-03 · C-03-1 카드 등록 (10/8 · 토스 브랜드페이) — 자동 충전은 하지 않고 카드 등록까지만. 결제는 지금처럼 단건(사용자가 [N크레딧 구매]를 누를 때마다), 등록 카드 + 결제 비밀번호로 결제.
        화면: C-03 ② 충전의 구매 버튼 위에 “결제 수단” 한 줄 — 미등록이면 “등록된 카드가 없어요” + [카드 등록하기] + 프로모션 한 줄, 등록되면 카드 목록을 같은 영역에 바로 표시(10/9 최소 스펙 — 별도 관리 페이지 없음): 카드 행 = 카드사 · ****끝 4자리 · ✓ 선택 · 🗑 삭제, 맨 아래 [＋ 다른 카드 추가]. 선택한 카드로 결제(requestPayment의 methodId), 기본 선택은 마지막으로 결제한 카드. 삭제는 확인 창 “카드사 ****1234를 삭제할까요? / 삭제한 카드는 다시 등록해야 결제에 쓸 수 있어요.” — 삭제해도 프로모션 크레딧은 회수하지 않고, 같은 계정은 재등록해도 재지급 없음. 기본 카드 지정 · 비밀번호 변경 UI는 만들지 않음. 카드 없이 [구매]를 눌러도 결제 가능(토스가 등록 → 결제 순서로 진행).
        토스 연동: 브랜드페이 SDK — tossPayments.brandpay({ customerKey, redirectUrl }) · 등록만 addPaymentMethod() · 결제 requestPayment()(KRW만) · 관리 openSettings()(카드 추가/삭제 · 비밀번호 변경 · 탈퇴). customerKey는 이메일 · 순번처럼 유추 가능한 값 금지 → 내부 UUID. 등록 완료 시 redirectUrl로 code · customerKey 전달 → 서버에서 Access Token 발급(grantType=AuthorizationCode) → 토큰은 결제수단 조회 · 회원 탈퇴 처리에 사용. 키는 브랜드페이용 API 개별 연동 키(live_ck) — 기존 결제위젯 키(live_gck)와 다름. 결제 어드민에 브랜드페이 서비스 추가 · 리다이렉트 URL 사전 등록 필요.
        결제 경로(10/12): 카드 등록 결제를 기본으로 크게(결제 수단 영역 + [N크레딧 구매]), (10/12 수정) 결제 수단을 라디오 2개로(리디 방식): ① 등록 카드로 결제(기본 선택, 위) — 카드 없으면 라디오 옆 “🎁 5크레딧 받기” 뱃지 + 강조 버튼 [🎁 첫 카드 등록하고 5크레딧 받기](유효기간 3일은 화면에 표시하지 않고 지급 토스트 · 크레딧 내역 만료 딱지로 안내), 카드 있으면 오른쪽 위 [결제 관리](10/14 — brandpay.openSettings()로 토스 결제 관리 화면: 결제수단 관리 · 결제 비밀번호 설정 · 원터치결제 · 생체인증 설정) + 카드 목록(선택 · 다른 카드 추가 — 10/14 삭제 버튼 제거, 삭제는 [결제 관리] 토스 화면에서) — 장수와 관계없이 모두 표시 ② 일반 결제(아래, 설명 없음) — 기존 토스 결제위젯(카드 · 토스페이 등). 아래 [N크레딧 구매] 하나로 결제. 별도 프로모션 띠 · “카드가 없으면 등록 화면이 먼저 열려요” 안내 · 텍스트 링크는 제거. 오픈 후 4주 일반 결제 비중을 보고 유지 · 제거 판단.
        첫 충전 보너스(10/12): 계정의 첫 유상 충전에 ⌊N/2⌋크레딧 보너스(무상) — 10 → +5 · 20 → +10 · 100 → +50 · 500 → +250, 직접 입력도 동일(내림). 결제 경로와 무관(카드 등록 결제 · 일반 결제 모두). 프리셋 카드 “첫 충전 +N 보너스”(10/12 상단 안내 배너는 제외) + 직접 입력 금액 줄 + 구매 버튼 “N크레딧 구매 · 보너스 +M”, 첫 충전 후에는 모두 숨김. 크레딧 내역에 결제 건과 별도 줄 “첫 충전 보너스”. 확인 필요: 보너스 유효기간(무상 14일 정책 적용 여부) · 첫 충전을 환불하면 보너스 회수(미사용분) 여부 · 최대 250크레딧 지급 원가 부담 · 카드 등록 5크레딧과 중복 지급 허용(현재 허용 가정).
        프로모션(오픈 후): 카드 등록 시 5크레딧(무상) · 계정당 1회 · 지급일로부터 3일 동안 사용 가능(10/9 — 일반 무상 크레딧 14일보다 짧게) · 환불 대상 아님. 카드를 삭제해도 지급분은 회수하지 않음. 프로모션 기간에만 [카드 등록] 옆 한 줄 노출, 크레딧 내역에 “카드 등록 프로모션”으로 표시.
        회원 탈퇴(C-10-1): 탈퇴 시 브랜드페이 회원 탈퇴 API도 함께 호출(등록 카드 정보 삭제).
        확인 필요: 등록 카드 목록(카드사 · 끝 4자리 · methodId)을 서버에서 조회 · 삭제할 수 있는지(브랜드페이 결제수단 조회 · 삭제 API, Access Token 필요) · 같은 카드로 여러 계정 프로모션 받는 것 막을 기준(카드 식별값 제공 여부) · 브랜드페이 계약 · 수수료가 기존 결제위젯과 같은지 · 개인정보 처리방침 위탁 항목에 브랜드페이(결제수단 정보 보관) 반영.
