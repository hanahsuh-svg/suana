💳 결제·환불 체계 도입 버전 (Current)

유저 콘솔 · 운영 어드민 · 자동 메일 세 층에 결제와 환불 흐름을 새로 얹은 버전입니다. 유저 콘솔에는 환불 버튼을 두지 않고, 모든 환불은 문의로 접수해 어드민에서 처리합니다.

🔄

C-03 크레딧 - 전면 개편

  • 기존 크레딧 관리 및 충전(제공 전/후 토글, 자동 충전 설정, 결제 모달)을 단일 화면으로 교체
  • 결제 내역 → 크레딧 내역으로 확장 — 지급 건과 결제 건을 한 표에, 컬럼은 일시·크레딧·결제금액·주문번호·상태
  • 만료는 평소 감추고 30일 이내일 때만 상태 컬럼에 “N일 후 만료” 딱지
  • 환불 안내 블록 상시 노출 — 환불 요청 버튼 없이 help 메일로만 접수
  • 사이드바 라벨 🎁 크레딧 안내 → 💳 크레딧으로 통일
🆕

O-04 결제·환불 관리 - 어드민 신규 화면

  • 환불 관리 큐 + 결제 내역 2탭. 담당자가 주문번호 조회 → 환불 건 등록, 등록 즉시 잔여 크레딧 동결
  • 상태 3종 — ⏳ 처리중 / ✓ 완료 / ⚠️ 취소. [완료 처리]는 PG 결과 “성공” 선택 시에만 활성
  • PG 취소는 토스 상점관리자에서 수동 실행하고 결과만 입력
  • 카드 결제만 제공 전제로 경고 분기·환불계좌 입력 없음. 잔여 0·중복 접수·결제 1년 초과 건은 조회 단계에서 등록 차단
  • 환불 가능액 = 결제 건별 잔여 × 크레딧당 결제단가 (토스 취소 API가 결제 건 단위이므로)
🆕

E-07 · E-08 - 결제·환불 자동 메일 2종 추가

  • E-07 충전 완료 안내 — 공급가액·부가세·결제 금액과 크레딧 차감 순서·환불 안내 포함
  • E-08 환불 완료 안내 — 카드사 반영 3~5영업일 경고, 부분 환불 시 조건부 블록 노출
  • 서비스명·문의 메일을 {company_name} 변수로 표기 (E-01~E-06은 아직 하드코딩)

Quickstart

Morph API는 OpenAI 표준 규격을 완벽하게 지원합니다. 기존 코드에서 Base URL과 API Key만 변경하여 즉시 사용할 수 있습니다.

1. API Key 발급

콘솔에 로그인하여 API Keys (C-02) 메뉴에서 Bearer 인증에 사용할 Secret Key를 발급받습니다.

2. cURL 예제 (Chat Completions)

curl -X POST https://api.morph.com/v1/chat/completions \
  -H "Authorization: Bearer $MORPH_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "motif-3",
    "messages": [
      {"role": "system", "content": "You are a helpful assistant."},\br/>       {"role": "user", "content": "Hello!"}
    ],
    "stream": true
  }'

서비스 이용약관

제 1조 (목적)

본 약관은 (주)모프컴퍼니(이하 "회사")가 제공하는 Morph Token Factory 서비스(이하 "서비스")의 이용과 관련하여 회사와 회원 간의 권리, 의무 및 책임사항, 기타 필요한 사항을 규정함을 목적으로 합니다.

제 2조 (용어의 정의)

① "회원"이란 본 약관에 동의하고 가입 절차를 거쳐 회사가 제공하는 서비스를 이용하는 자를 말합니다.
② "크레딧"이란 서비스 내에서 API 호출 비용 등을 결제하기 위해 사용되는 가상의 선불/후불 결제 수단을 의미합니다.

제 3조 (약관의 게시와 개정)

① 회사는 본 약관의 내용을 회원이 쉽게 알 수 있도록 서비스 초기 화면이나 연결 화면을 통하여 게시합니다.
② 회사가 약관을 개정할 경우에는 적용일자 및 개정사유를 명시하여 현행 약관과 함께 제1항의 방식에 따라 그 개정약관의 적용일자 7일 전부터 적용일자 전일까지 공지합니다.

전제 · 동선
  • 유저 콘솔(C-03)에 환불 버튼 없음 — 모든 환불은 help 메일로 접수
  • 담당자가 이 화면에서 건을 직접 등록해 처리 (등록 = 동결 = 처리중)
  • PG 취소는 토스 상점관리자에서 수동 실행, 여기에는 결과만 입력
  • 핵심 동선: 주문번호 입력 → [조회] → 계산 자동 표시 → 등록
  • 결제 내역 탭의 행에서도 [환불 등록] 진입 — 주문번호가 채워진 상태로 모달 오픈
상태 3종 (수동 운영 기준)
  • ⏳ 처리중 — 등록되는 순간 시작. 등록 시 잔여 크레딧 자동 동결
  • ✓ 완료 — PG 취소 성공 결과 입력 후 종결. 동결분은 차감 확정
  • ⚠️ 취소 — 고객 철회 / 잔여 0 / PG 취소 실패 등으로 종결. 동결 자동 해제, 사유 입력 필수
  • ‘접수’는 별도 상태로 두지 않음 — 메일을 받아 담당자가 등록하는 순간이 곧 처리 시작
  • [완료 처리]는 처리 결과 “성공” 선택 시에만 활성 (와이어프레임은 비활성 상태)
계산 규칙 · 결제 건 단위
  • 크레딧당 단가 = 결제금액 ÷ 충전 크레딧 (15,400 ÷ 10 = 1,540원)
  • 환불 가능액 = 이 결제 건의 잔여 × 단가 (6.42 × 1,540 = 9,887원, 원 단위 절사)
  • 토스 취소 API는 결제 건(paymentKey) 단위 — 계정 잔액 단위 취소는 없음
  • 한 회원이 전액 환불을 원하면 결제 건 수만큼 환불 건을 각각 등록. 잔여는 FIFO(먼저 산 것부터 차감) 기준으로 건별 계산
  • 무상 크레딧은 결제 건이 없으므로 환불 대상에서 제외
  • 계산 기준 시점은 동결 시점 — 등록 후 사용분은 반영하지 않음
